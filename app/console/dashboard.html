每行一个服务账号：粘贴完整 SA JSON（含 client_email / private_key / project_id）+ 可选 Project ID 覆盖 + 区域。SA JSON 输入框留空 = 保持该账号原值不变。凭证只回显掩码（client_email + project + location），永不回填 JSON。

混合自动：默认按下面的优先级顺序尝试；也可选择每次请求完全随机排列已勾选通道，再按随机顺序故障转移。限流/5xx/未出流失败自动切换下一通道；400/401/403 如实报错不切换；任一通道连续失败自动熔断冷却（阈值/冷却见模型参数页）。

生图下发 system 指令?
关闭时（默认）生图模型会丢弃 system 提示词——你写的画风、构图要求全部不生效。开启后 system 会随生图请求一起下发。

生图也注入预填充?

留空即用内置默认，一般不用改。
「智能」模式下它是那句续写指令，预填充文本会附在它后面；「保留模型轮次」模式下它就是末尾那句推动语。
若「保留模型轮次」老是重复开标签，可以把这里改得更短更像催促（例如只填 继续），减少“新一轮”的暗示。

标准模式 location?
作用：决定标准（Express）模式请求发到哪个区域，解决“偶发 404、报错里出现没见过的区域”。

为什么会 404：不指定时由 Google 后端自己挑区域，可能挑到不提供该模型的区域。
实测同一个 Key、同一个模型：gemini-2.5-pro 不指定 → 被路由到新加坡区域报 404；选 global → 正常出文。

默认 global：多数 Gemini 模型只在 global 提供，选具体区域反而可能 404，按需再换。

用哪个项目：自动使用「通道与凭证」里填的 Project ID（或环境变量 GOOGLE_PROJECT_ID）。两者都没有时自动退回不指定区域的旧方式。

注意：该项目必须是这个 API Key 有权、且已开启计费的项目。

失败会自动兜底：若上游回“模型不存在 / 需要计费”，代理会自动改回不指定区域重试一次，并在运行日志说明怎么修——所以这个设置不会让原本能用的配置变得不能用。

Google GenAI Client 复用（Express / 服务账号通道共用）
连接级失败自动舍弃阈值(次)?
作用对象：Express 与 服务账号两条 SDK 通道。google-genai 的 Client 复用了 httpx 连接池（省 TLS 握手）；但长驻进程里可能残留失效的 keep-alive 连接，导致连续的连接级错误（RemoteProtocolError / ConnectError / 超时）。
此开关开启时：缓存 Client 连续连接级失败达到阈值（默认 5 次，0=不自动舍弃）即自动舍弃，下次请求重建连接池。429 限流不算连接级失败（连接本身健康），不会误触发。安全策略拦截等硬错误会立即舍弃，不等阈值。
关闭此开关：每个请求都新建 Client（彻底避免复用失效连接），但失去连接复用、延迟开销增大——仅排查"复用后持续连接错误"时临时用。
防截断（Anti-Truncation）
启用字段名?
是什么：重提示词场景（酒馆复杂预设/角色卡/超长历史）下模型回答经常被 max_output_tokens 提前截断、丢尾巴坏格式。开启后，代理给请求注入一个请求级唯一的合成传输工具（v2o_emit_<随机数>），指示模型把最终可见回答放进该工具调用的 content 参数输出（Function Call 通道），从而绕开普通文本生成通道的截断；代理收到响应后解构还原为标准 assistant.content，对客户端完全透明，真实工具调用原样保留。

怎么用：下游请求体加「启用字段名」字段（默认 anti_truncation）置 true，即对该请求启用；不启用时完全不影响。字段名可改成客户端不冲突的名字。

注意事项：仅对文本/Chat 模型生效（生图/音频等自动忽略）；需要模型支持工具调用；与 tool_choice=none 冲突时以 auto 覆盖（否则合成工具不会被调用、防截断失效）；回答以工具参数整体输出、首字比普通流式略慢；不同模型对"工具输出"的截断保护效果不同，若发现仍被截断可配合调大「默认输出上限」。
输入搬运（全局）?
匹配标签名
替换占位语
剥离模型生成的同名已闭合块
三态开关：「不开」严格不改请求；「只在假流开」仅在该通道实际使用假流式时生效；「无论真/假流都开」则每次请求均生效。Cookie 文本通道本身不支持 fake- 假流式，选“只在假流开”时不会对它的普通文本请求改写。

用途：客户端把最新输入完整包在上面配置的 XML 元素里（宏会先由客户端替换为真实文本），网关便提取元素内载荷，追加到前一条 assistant 消息尾部，再把 user 消息替换为这里的占位语。只做楼尾追加，不支持其它插入位置。

安全护栏：标签与占位语没有任何默认值；模式不是“不开”但任一留空，网关严格不改请求。标签必须独占整条最新 user 纯文本，且前面必须存在一条普通 assistant 消息；图片、多段内容、工具调用历史或夹带标签外文字都会跳过，避免静默丢上下文。标签名仅允许字母/下划线开头及字母数字、_ . : -，最长 64 字。

剥离输出：打开后，模型自己生成的同名、已闭合块不会回传给客户端；流式标签跨分块也能识别。模型若输出半截未闭合块，流结束时会原样放行，不会吞字。

随机抽取?
随机模式会从所有有效方案中抽取一套。它让每轮请求前缀发生变化，通常会降低上游隐式上下文缓存命中率；仅在确实需要变体时打开。
作用：把最新 user 纯文本复制进一套内容方案，作为 system / AI / user 身份的消息插到所有提示词最前面；原始 user 消息不替换。每套方案可通过内部占位符 {{input}} 精确放置输入内容；不写占位符时，网关会把输入自动追加到方案尾部。

三态与输入搬运相同：不开、只在当前通道实际走假流时开启、或无论真/假流都开启。方案会持久化在控制台状态中，可固定选择或随机抽取。最新输入不是纯文本时会自动跳过，避免丢失多模态内容。

生图模型不受此开关影响（本来就强制假流式）；Cookie 直连通道没有假流式实现，fake- 前缀会被自动剥掉当普通模型处理。

预填充
思维链守卫?
解决“预设思维链经常不写、直接出正文”：预填充只是把话头停在 <思维链标签> 上，没有任何一句话告诉模型必须先完成思考，模型于是常常跳过思考直接写正文，前端正则就抓不到思维链。
打开后，代理会自动识别预填充里未闭合的开标签，在续写指令末尾追加一条硬性要求：先逐条写完该标签内的思考、用对应闭合标签收尾，然后才写正文。
没检测到未闭合标签时（例如预填充只是普通句子）本项不做任何事；生图模型不适用。
仍不稳定时：把「原生思考控制」从“关闭原生思考”改为“强制用上方档位 + low”再对比——压到 minimal 会让模型倾向“直接给答案”，可能连带跳过预设要求的长思考。
预填充兼容模式?
什么是预填充：请求里最后一条 assistant 消息（酒馆预设里通常是最底部那条“助手”条目，内容多为思维链的开标签）。它替模型写好了回复开头，模型只能顺着往下写——这是破限最强的杠杆，也用来顶掉原生思维链。预设里那些 system 条目不是预填充。
为什么需要兼容：Gemini 3.x 拒绝以 assistant 结尾的请求（400），必须改造成 user 结尾。

智能（默认）：删掉那条 assistant，把它的文字并进最后一条 user。模型视角＝“用户给了我一段参考文字”。输出干净（实测开闭标签各 1 个），但模型没有“说过”这句话，破限杠杆最弱。
保留模型轮次：assistant 原样留着，后面补一句很短的 user 推动语。模型视角＝“这是我自己写了一半的”，破限杠杆保留。代价是模型容易当成新一轮、把开标签再写一遍（实测 3/3）。
最小：只补占位 user 保证不报错，不把预填充拼回输出——思考开标签会缺失，前端正则可能抓不到。
关闭：原样发出，3.x 直接 400；而且代理检测不到预填充，思考压制也不会触发。

2.5 及更早的模型不受影响，走的是原生透传，效果等同老式预填充。
预填充时压制原生思考?
检测到预填充时，把模型的原生思维链压到最低并不回传，让预设自带的思维链接管（写作效果通常更好，也避免“只有思考没有正文”）。
3.x 压到最低档（无法完全关闭），2.5-flash 预算 0 全关，2.5-pro 降到 128。
只在请求真的带预填充时才触发；若你的预设把思维链写在 system 里、没有 assistant 条目，请改用上方“思考强度”卡片的“关闭原生思考”。
